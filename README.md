# Task Manager API

A task manager backend I built with FastAPI and SQLModel for the Week 2 assignment. It has login with JWT, hashed passwords (Argon2), and two roles: `user` and `admin`.

## What I used

- FastAPI
- SQLModel
- PostgreSQL (I used this instead of SQLite, it's set through `DATABASE_URL` in `.env`)
- JWT + Argon2 for auth

## How to run it

1. Clone the repo and go into the folder:

```
git clone <my-repo-url>
cd task-manager
```

2. Create a `.env` file in the main folder (next to `main.py`):

```
APP_NAME=Task Manager API
DATABASE_URL=postgresql+psycopg://postgres:postgres@db:5432/task_manager
SECRET_KEY=put-a-long-random-string-here
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=60
```

`DATABASE_URL` is what points the app to the database. For the secret key you can generate one with:

```
python -c "import secrets; print(secrets.token_hex(32))"
```

3. Start the project:

```
docker compose up --build
```

4. Open the docs at http://localhost:8000/docs

## Creating the first admin

You can't make an admin through the API (register always gives the `user` role). Run this in a second terminal while the app is running:

```
docker compose exec api python create_admin.py --username admin --email admin@example.com --password Admin12345
```

## Using /docs

1. Register a user with `POST /auth/register` (or use the admin you just made).
2. Click the **Authorize** button and enter your username and password.
3. Now you can call all the protected routes.

## Routes

**Auth**
- `POST /auth/register` - create a user
- `POST /auth/login` - login, returns a token
- `GET /auth/me` - who am I

**Tasks**
- `POST /tasks` - create a task
- `GET /tasks` - list tasks (filter by `status` and `priority`, plus `skip` and `limit`)
- `GET /tasks/{task_id}` - get one task
- `PATCH /tasks/{task_id}` - update a task
- `PATCH /tasks/{task_id}/complete` - mark as done (400 if it's already done)
- `DELETE /tasks/{task_id}` - delete a task

## Permissions

- A normal user can only see, edit and delete their own tasks.
- If a user asks for someone else's task they get a 404, same as if it didn't exist.
- An admin can see and manage everyone's tasks.
- Not logged in gives 401, logged in but not allowed gives 403.
- `user_id` comes from the token, not from the request body.

## Other notes

- Every task has an `FDATE` field with a random number, generated by the server when the task is created.
- A blank task title gives the error `TITLE_VALIDATION_17`.
- The password hash is never returned in any response.
